# 桌面柴犬（desktop-pet）

一只住在桌面上的柴犬：会追你的鼠标、会自己伸懒腰打滚，也能按分类把桌面图标一个个搬进区域，还能把不要的文件吃掉（送进回收站）。

狗的图形**不依赖任何图片素材**，全部由 Canvas 2D 每帧程序化绘制；桌面图标操作通过 koffi FFI 直接读写 explorer 的 `SysListView32`，不需要外部脚本或编译器。

---

## 功能

### 会动的狗

- **14 个行为状态**的行为机：待机 / 走 / 跑 / 喘气 / 开心 / 被拎 / 走去食盆 / 进食 / 搬运 / 伸懒腰 / 打滚 / 抓痒 / 追尾巴转圈 / 打哈欠
- **4 种漫游模式**：追鼠标（默认）、躲鼠标、自己闲逛、蹲点不跟随
- 闲下来会自己找事做：待机 1.5~4 秒后随机表演一个小动作，播完回待机继续循环
- 呼吸、摆尾、耳朵偶发抽动、随机眨眼（2.2~6.5 秒一次）永不停歇
- 三档外形预设（puppy / teen / adult），幼犬不是缩小版成犬：头更大、腿更短、耳朵没完全立、尾巴没完全卷

### 桌面整理

现在跑的是**最初那一种**：按分类把桌面图标挪进你画好的区域，只挪位置、文件不动。

- 按扩展名分类（文档 / 图片 / 视频 / 音频 / 压缩包 / 安装包 / 快捷方式 / 其他），把桌面图标**挪进**对应区域
- 只改图标在 explorer 里的显示坐标，**文件本身不动**，不产生任何磁盘写入，也不碰文件属性
- 狗逐个搬运：走到图标前扒拉一下 → 再走到区域里 → 落位那一刻图标出现在新格子上
- 支持整批撤销（记录每个图标的原始坐标，按显示名回匹，不怕 explorer 重排 index，也不受大小写影响）
- 显示缩放 125% / 150% 下同样准确：explorer 的物理像素坐标只在进出 FFI 时换算，区域、落点、狗跑动全程用 DIP
- 区域框可常驻显示，也可在整理时临时高亮；区域按图标网格对齐排布，从屏幕右边缘往左紧邻排列
- 会自动确保 shell 的"自动排列图标"处于关闭状态，否则我们写进去的坐标会被系统复位

另外两套做过、验过、但**当前没有入口**的代码（要放开见下）：

- `CARRY_HIDE_ICON`（`src/main/organize.ts`，现在 false）：打开后是「衔到即消失」—— 狗叼起图标那一刻把文件临时打上隐藏属性让它真消失，嘴里画一张同分类的假图标跟着走，松口时显形并写到落点。配套的单测、崩溃找回（`carry.json`）都在
- 收纳进分类文件夹（`src/main/fold.ts` + `organize.runFoldOrganize`）：把散文件真的收进桌面的「文档 / 图片 / …」文件夹，再排成竖栏。会真的移动文件，所以动手前先弹清单确认（`src/renderer/pet/fold-panel.ts`），账本 `fold.json` 支持撤销与崩溃补账，沙盒验收 29 项全过。入口在 `ipc.askFoldNow`，菜单项与设置窗卡片加回来即可放开
- 只排整齐（`organize.runColumns` + `shared/fold.planColumns`）：不画区域，按类型自动分竖栏排齐，只挪坐标

### 投喂（吃文件）

- 把文件拖到狗身上或食盆上即可投喂，走系统回收站，**代码里不存在硬删除**，喂错还能捞回来
- 安全护栏：拒绝相对路径、符号链接、文件夹、`desktop.ini`/`thumbs.db` 等系统占位文件、Windows/ProgramFiles 等系统目录，单次上限 50 个
- 也可以在菜单里"喂文件…"用系统对话框挑

### 信息服务

- 点狗头报当天天气（wttr.in，免 key，按网络位置定位），**同时演一下对应这个天气的动作**：下雨甩水、下雪落肩、雾霾眯眼咳嗽、大风耳朵往后压、暴晒喘气、降温发抖夹尾巴、打雷惊一跳、晴天猛摇尾巴。一次点击只播 2~4 秒，自己停，不常驻、不打断追鼠标/吃饭/搬运
- 报天气那句只报**现在几度 + 一个中文天气词**（例：`🌤 现在 17℃ · 晴`），湿度风速紫外线那些不上气泡；天气码翻成中文常用说法，码没收录就退回英文描述里的关键词，再退回档位词，永远不会出现 `undefined` 或空的
- 那句气泡画在**狗嘴前方**（朝哪边就往哪边），不压狗头也不压雨丝雾带；贴到屏幕边放不下时才退回头顶
- 天气结果留 10 分钟缓存（连点狗头不反复打接口）；**失败的只压 30 秒**——网络抖一下就锁十分钟的话，她会反复点不出东西、以为功能坏了
- 点狗前胸口播一条今天的新闻（60s API，免 key）。原来是每小时自动推一条，一天里它自己会打断你好几次，现在改成想听才点。该源每天只更新一次，所以做了**当天内容去重轮流播**：一轮内每条只播一次，全播完自动开下一轮，换天重置；批次留 1 小时，抓失败只压 30 秒。实测今天 15 条、最长 52 字，气泡三行的额度说得完、不会被截成半句

### 交互速查

| 操作 | 反应 |
| --- | --- |
| 左键点狗头 | 播报天气（只报现在几度 + 什么天气），并演一下这个天气（一次性，几秒后自己停） |
| 左键点狗前胸口 | 播一条今天的新闻（每条只播一次，点完一批自动开下一轮） |
| 左键点狗屁股 | 触发桌面整理 |
| 左键点身体其他处 | 抚摸，开心跳 |
| 左键按住拖动 | 拎着狗走，松手落地（横向净位移超过 16px 才翻朝向，点击手抖不会让它甩头） |
| 右键 | 玻璃功能菜单（自绘面板；系统托盘吃同一份数据，勾选状态永远一致） |
| 拖文件到狗 / 食盆 | 投喂 |
| 鼠标移到别处 | 狗的脸朝着你（指针进入身体范围时冻结朝向，保证点得准） |

菜单头部两行：**第一行是狗的名字**，在「设置 → 小狗」里自己起（最长 12 个字，空的或全是空格会退回默认名「小柴」，存档里的名字每次读档都按同一套规则洗一遍：去首尾空格、压掉连续空白、剔掉换行）；**第二行小字是「陪主人一共 N 小时」**，按本次启动到现在的实际时长数满几小时，不满一小时也说 1 小时。原来这行报的是漫游模式和保持距离，那两样在勾选框和设置窗里都看得到，占一行小字反而没人读。

菜单只留常用的 8 项：**陪玩**（跟随鼠标 / 回到食盆旁）、**干活**（整理桌面 / 喂文件…）、**窗口**（始终置顶 / 隐藏小狗 / 设置… / 退出）。低频项一律不进菜单，免得每次都要在一堆里找：撤销上一次整理、区域框开关在「设置 → 整理桌面」里；「开发者工具」只有用 `PET_DEV=1` 启动才出现一行「打断点调试」，正常用时看不到。

三个部位分得开：头是头顶那一块圆，**前胸口**取 `chestAnchor()`（躯干最前面往里一点、肚子和背的中间高度，半径 = 头半径 ×0.9），屁股取包围盒靠后的 1/3。三者互不重叠，判定顺序是头 → 胸口 → 屁股 → 其余算抚摸。所以点胸口不会同时触发整理，也不会被当成摸。实测（`docs/wx-check`）胸口那块圆有 **82.9%** 落在真画出来的狗身上（头顶圆 53.9%、屁股矩形 37.1% —— 后两个是本来就偏宽松的判定，点在边缘空地上也算）。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 桌面容器 | Electron 44（透明置顶窗 + `setShape` 命中区裁剪） |
| 语言 | TypeScript 7，严格模式 |
| 构建 | Vite 8（渲染层）+ tsc（主进程 / preload） |
| 图形 | 原生 Canvas 2D，零图片素材 |
| 系统调用 | koffi 3（预编译二进制，免本地编译器）跨进程读写 explorer 列表视图 |
| 界面材质 | [Solid Glass](https://github.com/deeplethe/solid-glass) 玻璃主题，随包源码在 `src/renderer/glass/`（MIT，见该目录下的 LICENSE）。旋钮取浅色 + `sg-tint-warm`（奶油底）+ `sg-accent-amber`（蜂蜜强调）+ `sg-rim-soft` + `sg-radius-large`；主题默认的冷灰阴影/发丝线在 `styles.css` 顶部那一组 `:root` 变量里统一调成暖色相，狗气泡、菜单、设置窗、收纳确认面板同一套色 |
| 测试 | Vitest 204 例：分类规则、收纳清单与分栏落点、整理计划与网格落点、显示缩放单位换算、行为机（含搬运被打断后续搬、转圈翻面次数、掉头必须重报命中区）、狗嘴假图标的出现与缩没、气泡折行与嘴前方定位、新闻轮播去重与换天重置、隐藏属性改写与显示名回匹、收纳账本清洗、存档清洗（含狗名清洗）、投喂护栏、菜单数据源与陪伴时长、天气档位判定与一次性效果层 |

运行环境：Windows 10/11，Node.js 20 及以上。

## 快速开始

```bash
npm install
npm run dev        # tsc watch + vite HMR + electron，控制台保留日志
```

如果 electron 二进制下载失败（国内网络）：

```powershell
$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
node node_modules\electron\install.js
```

日常使用可以直接双击仓库根目录的批处理：

- `启动宠物.bat` — 构建后启动，并自动关闭控制台，桌面上只留一只狗
- `启动宠物-开发.bat` — 开发模式（带日志）；追加参数 `debug` 显示命中区框，追加 `puppy|teen|adult` 预览某个体型

### 三个窗口的分工

1. **狗窗**：铺满工作区的透明置顶窗。用 `setShape` 把命中区裁到"狗 + 食盆 + 气泡"，其余位置鼠标直接穿透到桌面，所以狗不会挡住你干活。
2. **装饰层窗**：全程点击穿透的独立窗口。Windows 的 `SetWindowRgn` 会**同时裁剪绘制和命中测试**——画在狗窗热区外的东西根本合不出来，所以区域框必须交给这扇窗画。
3. **设置窗**：普通窗口，编辑分类规则与区域、调跟随距离等。

主进程把状态变更同时广播给狗窗和装饰层，两窗共用一份渲染产物、按 `?view=` 分支区分职责。

### 渲染的四个层次

```
DogParams（骨骼尺寸）→ Dog 行为机（决策）→ Pose（单帧姿态）→ shiba.ts（绘制）
```

- **绘制函数只读 Pose，绝不自己算时间**，所以加一个新动作只要写一个"填 Pose"的函数
- 坐标系巧思：`scale(dir * scale, -scale)` 把 y 轴翻转，于是所有高度都写正数；朝向 ±1 直接乘进 scale，狗只画一遍就能左右翻
- 动画两类驱动：循环型 `sin(clock * TAU * 频率) * 幅度`；一次性动作先归一化进度再取 `sin(t * PI)` 得到 0→1→0 的钟形包络
- 四腿步态靠跨帧累加的 `legPhase`，远侧腿相位差 π，自然形成对角线步态

### 性能取舍

- **脏矩形重绘**：每帧只 `clearRect`「狗框 + 食盆 + 粒子包围盒 + 气泡实际区域 + 上一帧脏区」的并集，不整块清 1920×1080
- **命中区上报带迟滞**：狗走出一大步才重设 `setShape`，否则每帧触发 `SetWindowRgn` 会让窗口边缘白边闪烁；拖动和搬运时干脆把命中区一次性放大到整块画布。**但掉头那一帧必须立刻重报**：狗身体两侧宽度不一样（成犬朝头那侧伸出 144px、朝屁股那侧 77px），区域留在旧朝向时，`setShape` 会把新朝向那侧约 67px 直接裁掉，看起来就是「掉头时狗头少了一块」。判定抽成 `shapeNeedsReport()`，有单测
- **随机小动作「追尾巴转圈」一圈只翻两次面**：原先拿正弦按帧翻，实测一秒翻 9 次，看着不像转圈而像画面故障。现在 1/3 处转过去、2/3 处转回来，配压低重心，`test/dog.test.ts` 钉住了翻面次数
- 尺寸随内容变化的绘制物（长文本气泡）必须把自己的实际绘制框反馈给帧循环入脏区，否则会留下永久白色残影
- **天气那层比狗身宽，得一起进命中区**：`SetWindowRgn` 同时裁绘制，雨丝雪片只入脏区不够，还要在 `hotRects()` 里把 `paintBox()` 那块要进来，否则会被沿狗框边缘整齐切掉。效果停掉那一帧 `dirty()` 会多报一次最后画过的位置，专门用来擦残留（只报一次，不会一直占着脏区）
- **气泡不许盖住动画**：报天气那句改成「短句子 + 挂在嘴前方」（`fx.say(text, 4.5, "front")` → `bubbleAnchor()` 取狗身朝前的那条边当基准，朝哪边就往哪边，只有贴到屏幕边放不下时才退回头顶）。反向放会正好压在狗自己身上（嘴后面就是头和身子），所以不做左右翻转兜底。按**像素**量（狗是不规则剪影，比包围盒诚实）：老做法一帧最多盖掉 134 个动画像素、压在狗身上 50 个；新做法两种都是 0。长句子的折行按摆法给两套额度：嘴前方最多两行、一行 236px（天气那句本来就短）；头顶最多三行、一行 320px（一整条新闻要说得完）。折行优先在空格和中文标点处断，断完还超行数就整体按等宽重排（不然第一行只占三分之一，后半条新闻会被省略号吃掉）
- **天气效果「有没有画」不等于「看不看得见」**：狗窗是透明窗，一层 10% 的雾血压在你的桌布上等于没画。用 `docs/wx-check` 那个测量页（`node docs/wx-check/build.mjs`，再用浏览器打开产物读 `window.__wxRows`）把每档量化了一遍——同一帧画两遍（叠天气 / 不叠），数 alpha 变化 ≥16% 的像素数。改之前：雾霾 1191、阴天 722、发抖 1403（对比下雨 7494、打雷 31266），所以点狗头只看到字、看不到动作；改之后：雾霾 29626、阴天 3602、大风 11882、暴晒 16571、发抖 2644（发抖这种「整只狗在颤」的动作按像素数天然吃亏，看的是位移不是色差）

## 存档与配置

都在 `app.getPath("userData")` 下（Windows 上是 `%APPDATA%\desktop-pet\`）：

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 置顶、漫游模式、跟随距离、是否显示区域框、狗的名字 |
| `config.json` | 分类规则（扩展名/颜色）与自定义区域（位置、绑定分类、是否启用） |
| `organize.json` | 整理会话的撤销栈（每个图标的原始坐标） |
| `fold.json` | 收纳账本（每个文件从哪搬到哪、文件夹是不是新建的、有没有搬成）。撤销与崩溃补账都照它 |
| `carry.json` | 狗嘴里正叼着（临时隐藏）的那一个文件：路径、原属性、原坐标。崩溃后靠它恢复 |

读写都是"剥 UTF-8 BOM + 先写临时文件再改名 + 400ms 去抖合并"，用户用记事本手改配置不会把应用带进沟里；任何字段异常都回落到默认值，存档没有能力炸掉启动。

## 平台限制

- **仅支持 Windows**。整理依赖 explorer 的 `SysListView32` 消息接口，所有 FFI 调用都包了 try/catch 并在拿不到窗口时优雅降级（Win11 24H2 等结构变动不会崩应用）。
- 整理前需要 shell 的"自动排列图标"处于关闭状态，程序会尝试自动确保；失败时图标会被系统复位。
- 公共桌面项可能因权限不足而拒绝投喂/挪动，会明确回报"没权限"而不是静默失败。收纳模式只往**用户自己的桌面目录**里搬文件，公共桌面上的项直接跳过并说明原因。
- 收纳模式（代码留着，当前没有入口）会真的移动文件，所以：动手前先弹清单确认；目标文件夹里已有同名文件的那一个直接不收（绝不覆盖）；账本 `fold.json` 只认「从桌面搬进桌面下的分类文件夹」这一种形状，路径不合法或指向桌面外面的一律丢掉，撤销时还会再验一遍位置。
- 收纳搬到一半进程没了：下次启动只做安全补救（把带着隐藏属性卡在文件夹里的文件显形、把账补上），**绝不自动搬文件**，只报告「有 N 个上次没搬成，原地没动」。
- 「衔到即消失」开关（`CARRY_HIDE_ICON`）打开时才有下面两条：叼图标会临时给那个文件加上"隐藏"属性（约 0.1~0.3 秒），这期间它在资源管理器里也是隐藏的；正常退出、拎狗、撤销都会立刻改回来，进程被强杀则下次启动照 `carry.json` 补做。公共桌面上的项没有写权限时自动退回"到落点才挪"。
- 藏 / 现各让 explorer 重读一次那个文件所在的目录（`SHCNE_UPDATEDIR`），只刷这一个目录，不重画整份桌面，所以不闪屏。个别系统上如果这种通知叫不动桌面列表，才退回按一次 F5（那会整屏重画、并取消桌面上已选中的图标），代码里记住哪种管用，不会每个图标都白等一轮。
- 天气与新闻是免费公开 API，无 SLA；请求带 8 秒超时，失败就什么都不说、也**什么都不演**（宁可不演，也不照着猜一个不相干的动作）。成功的天气留 10 分钟缓存、成功的新闻批次留 1 小时；**两种失败都只压 30 秒**，网络抖一下不该让你半小时内点了都没反应。
- 右键菜单没有键盘上下选择：狗窗是 `focusable:false`（摸狗不抢你的打字焦点），代价是收不到键盘事件，只能鼠标点或点外面收起。
- 玻璃面板**不会模糊真实桌面**：Chromium 的 `backdrop-filter` 只能糊同一页面里的内容，透明窗后面是系统桌面，采样不到。所以面板内部垫了一层主题自带的光晕，玻璃质感来自这一层而不是桌面。

### 整理叼运的实测结论

「让图标跟着狗嘴走」和「把图标挪到屏幕外藏起来」都实测过，结论记在这里，免得以后再试一遍：

| 想做的事 | 实测结果（1080p / 100% 缩放，自动排列已关闭） |
| --- | --- |
| 图标停在任意像素 | 不行。桌面只接受格点，写 300,333 读回 318,305；格距 76×101，原点 (14,2) |
| 把图标写到屏幕外（-3000,-3000） | 被夹回左上第一格 (14,2)，仍然看得见 |
| 把图标写到超大坐标（5000,5000） | 被夹回右下最后一格 (1838,911)，仍然看得见 |
| 靠 `LVM_SETITEMPOSITION32` 的返回值判断写成功 | 不可靠：被夹回来也返回成功，所以藏之前一定读回核对 |
| 改隐藏属性后用 `SHChangeNotify` 让图标消失 | 属性通知 / 更新项 / 视图刷新三种都叫不动桌面列表。pidl 传法没真正测到：`ILCreateFromPathW` 在本机 koffi 调用下没建出 pidl |
| 同上，改用 `SHCNE_UPDATEDIR`（重读这个文件所在的目录） | **可行且不闪屏**。藏 / 现各约 100~140ms，桌面图标总数只在 24↔23 之间变一次 |
| 同上，改用 `SHELLDLL_DefView` 收一个 F5 | 也可行，但整份桌面重画：图标总数瞬间掉到 0，就是肉眼看到的「屏幕一闪」；桌面选中项会被取消。现在只当兜底 |
| 藏之前先把坐标写到落点，指望显形时留在那儿 | 用 `UPDATEDIR` 时可以：实测写 1374,507 → 藏 → 现，仍停在 1374,507。用 F5 时不行，会被塞进第一个空格 |

所以「衔到即消失」那套的做法是：起叼前先把落点坐标写好，再改隐藏属性；用 `UPDATEDIR` 刷这一个目录；放下时取消隐藏，图标直接冒在目标格子里，最后再按名字核对一次落点（`putBack`，最多等 1.4s）。这个开关现在关着（`CARRY_HIDE_ICON = false`），表里的结论是给重新打开时用的，不用再把 Windows 桌面的这些限制试一遍。
